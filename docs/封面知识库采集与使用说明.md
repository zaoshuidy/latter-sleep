# 封面知识库采集与使用说明

## 当前状态

本库用于积累中国图书封面设计案例。空库和不足 50 条有效案例时状态均为 `building`，不得对外标记或报告为可用。只有 50 条案例全部通过完整校验后，状态才是 `available`。

本说明只规定采集、验收、使用和维护流程，不在此创建定时任务，也不替代人工审核。

## 单条案例验收标准

每条候选必须同时满足：

1. 属于中国图书设计，出版年份为 2017—2026 年（含首尾年份）。
2. 来源页面能看见封面；保存案例直接页面 URL，不把搜索结果页当作来源依据。
3. 登记来源平台、采集日期和书名。设计者、出版社只在来源明确写出时登记，来源未说明时填 `null`，不得猜测或补造。
4. 保存原始下载的、可正常解码且可辨认的 JPEG、PNG 或 WebP 文件字节，不用截图重制品替代可获得的原图；直接页面 URL 与原始文件均须保留。
5. 图片 SHA-256 在封面库内唯一，`book_case_id` 在封面库内唯一。同一本书或同一图片不得伪装为多个独立案例。
6. 新验收记录的生命周期从 `accumulation` 开始；不得把未核验素材标记为已授权或已确认。

任何看不清、来源无法直达、年份无法确认、图片不可读或事实互相冲突的候选均不进入正式记录；先保留为待核验材料。

## 来源优先级

按以下顺序采集，并优先补足尚未覆盖的年份、视觉策略和构图类型：

1. 中国图书设计相关官方奖项、机构和正式展陈页面。
2. 出版社、设计师或设计工作室的公开项目页面。
3. 专业出版或设计媒体、展览页面。
4. 社交平台只用于补足多样性缺口；需要发现小红书等平台内容时，调用项目已有的抓取 Skill，并保留发现后的直接帖子 URL。

社交发现不能降低验收标准。所有事实以直接案例页可见信息为准，永远不根据搜索摘要、文件名、平台习惯或常识发明设计者、出版社、年份等信息。

## 编号与入库

编号只在候选通过验收时分配，并按接受顺序连续使用：

- 来源编号：`SRC-CN-0001` 至 `SRC-CN-0050`。
- 封面记录编号：`COV-CN-0001` 至 `COV-CN-0050`。

空登记表不预留来源，不创建占位记录。验收后，把来源写入共享 `source-registry.json`，把原始图片写入 `cover/assets/`，把人工记录写入 `cover/records/`。`catalog.json`、`retrieval-index.json`、`categories/*.json` 和 `manifest.json` 只能由构建器更新，不得手工修补。

```bash
.venv/bin/python scripts/book_component_kb/build_library.py \
  --component-root knowledge/book-component-libraries/cover \
  --registry knowledge/book-component-libraries/source-registry.json

.venv/bin/python scripts/book_component_kb/validate_library.py \
  --component-root knowledge/book-component-libraries/cover \
  --registry knowledge/book-component-libraries/source-registry.json \
  --required-count 50
```

校验退出码 `0` 表示完整且可用，`2` 表示结构有效但仍为 `building`，`1` 表示无效。达到 50 条不等于自动可用：还必须保证 50 本书、50 个记录和 50 份图片均唯一，来源、原始文件、哈希、派生索引与 manifest 的完整链路全部通过校验。

## 使用与回流边界

检索和设计引用只能使用已经进入库且通过校验的记录。已有且经认可的生成图片，也只能经过 Task 7 的回流提案并获得项目负责人明确人工批准后进入知识库；模型评分、审核通过、沉默或继续执行均不构成批准，禁止自动晋级。

## 每周维护（仅流程，不设定时任务）

每周人工执行一次：

1. 运行完整校验，确认来源绑定、图片解码、哈希和派生文件一致。
2. 复查重复图片、重复书目、失效或错误来源、事实缺失和图像质量问题。
3. 对不再适用的原图和记录做归档，不自动删除；保留审计线索。
4. 所有变更完成后只通过构建器更新 catalog、分类、检索索引和 manifest，再重新校验。

本阶段不创建计划任务；维护结果由人检查并确认。
